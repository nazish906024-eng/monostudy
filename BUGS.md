# Bug report — what was wrong and where it's fixed

## Blockers (app could not run)
| # | File | Bug | Fix |
|---|---|---|---|
| 1 | server.js | `require("./chapter-data.json")` — file not in the project → server crashed on start | Created `chapter-data.json` (106 chapters, ids match the PYQ `chapterId`s; generated by `tools/build-data.py`, which also validates links) |
| 2 | style.css | Upload contained only the login-screen rules: no `:root` colours (`--bg`, `--panel`…), no layout, `.hidden`, `.panel`, `.opt`… so the app was unstyled and `.hidden` forms stayed visible | Wrote the full stylesheet; auth rules kept at the bottom |
| 3 | index.html / app.js | Login screen (`#authScreen`, tabs, OTP, Google, guest, logout) existed in HTML but **no JS** was attached; it covers the whole app (`position:fixed; z-index:1000`) so nothing was clickable | `initAuth()` wired to every control; screen is hidden unless signed out |
| 4 | app.js | Data loaded with `fetch()`; browsers block that on `file://`, so chapters and PYQs never loaded when opening the file directly | Data ships as `chapter-data.js` / `pyq-data.js` (`<script>`); fetch is only an optional refresh over http |
| 5 | service-worker.js | `cache.addAll()` lists `icons/icon.svg` and `chapter-data.json`, which didn't exist → one 404 aborts install, so no offline/PWA | Files added; precache is per-file and can't abort |
| 6 | index.html / manifest | `icons/icon.svg` missing; install needs 192/512 PNG | Added SVG + PNG icons, manifest updated |

## Server bugs / hardening
| # | Bug | Fix |
|---|---|---|
| 17 | Chapter status was **global**: every visitor shared one progress file | Per-user (token, else `X-User-Id`) |
| 18 | `user_id` accepted from the body with no auth: anyone could write another user's attempts | A valid token always overrides the body field |
| 19 | Request to `//` threw `Invalid URL` → 500; no HEAD support; `decodeURIComponent` errors | Normalised path, 400 on bad URLs, HEAD served |
| 20 | Writable state sat next to the code | Moved to `data/`, static server uses a strict whitelist (users.json etc. return 404) |
| 21 | CORS headers didn't allow `PUT` / `Authorization` | Added |
| 22 | Service worker `respondWith(undefined)` when offline and uncached | Falls back to cached `index.html` / `Response.error()` |

## Interconnections added
- Login → per-account storage bucket → server token → `/api/v1/state` cloud sync → second device sees the same data (tested).
- Imported question files → vault, error log, analytics, backups, cloud sync.
- `build-data.py` keeps JSON, JS twins and chapter ids consistent.

## Not fixed on purpose / still open
- Google sign-in (needs your OAuth client ID) and real SMS OTP (needs a provider).
- Weightage/frequency values are estimates, not audited data.
- `localStorage` is ~5 MB; many note images will hit it (the app warns and the server sync rejects >12 MB).
- Last-write-wins sync: editing on two devices at the same time keeps the newer save.

## Added in v4 (Firebase)
- Service worker now bypasses `googleapis.com` etc. (Firestore's long-lived GET streams would otherwise be cached/broken); cache bumped to v4.
- `server.js` static whitelist includes the two new scripts.
